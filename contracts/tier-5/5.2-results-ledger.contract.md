# Tier 5.2 — Results Ledger (artifact-based)

## Purpose
Run a "virtual test" for a (snapshot_id + scenario_id) and store results
as an immutable artifact/report record.

## Key Rule
- NEVER write results into the snapshot.
- Results are stored as separate records/artifacts.

## Inputs
- snapshot_id
- scenario_id
- optional baseline_snapshot_id (for deltas)

## Output (TestingResult)
- result_id
- snapshot_id
- scenario_id
- metrics (Tier 4.4 output)
- summary (stable text)
- deltas (optional)
- created_at
- created_by
- job_id (if async)

## Invariants
1) Snapshot is never mutated
2) Execution is async-job based
3) Same snapshot + scenario yields deterministic metrics (Tier 4.4)
4) Missing inputs degrade confidence, never crash
5) Viewer can READ results; only editor/owner can RUN jobs (recommended)

## API
POST /snapshots/{snapshot_id}/testing/run
GET  /testing/results/{result_id}

### POST behavior
- Validates snapshot exists
- Validates scenario exists
- Creates async job
- Audits: testing.run.requested
- Returns { job_id }

### GET behavior
- Returns stored result (immutable)
- 404 if missing
