# Tier 7.58 — Constraint UX

## Purpose (LOCKED)
Expose constraint violations clearly in the editor so governed blocks are
understandable and actionable.

## Inputs
- evaluate response from governed tool pipeline
- active selection
- active snapshot
- current scene objects

## UI Requirements
The editor must show:
- violation list panel
- per-violation:
  - kind
  - message
  - constraint_id
  - target_id if available
  - structured data if available
- blocked apply state when violations exist

## Canonical Violation Shape
{
  "constraint_id": "string",
  "kind": "string",
  "message": "string",
  "data": { ... },
  "target_id": "string"?   # optional in Tier 7.58
}

## Behavior
- evaluate failure with violations updates canonical violation store
- successful evaluate/apply clears prior violations
- clicking a violation may select/highlight the related object if target_id exists
- violations render in deterministic order

## Determinism
- same violation set => same UI ordering
- ordering priority:
  1) target_id
  2) kind
  3) constraint_id
- no random grouping or collapsing

## Invariants
- no snapshot writes
- no backend mutation from viewing violations
- one source of truth for visible violations

## Forbidden
- silent failure without visible reason
- stale violations remaining after successful commit
- divergent violation rendering in multiple panels
