# Tier 2.2 — Constraint Visualization (Read-Only)

## Purpose
Expose active constraints to users in a non-interactive, read-only manner.

---

## Scope

The UI MAY:
- Display active constraints
- Highlight constrained targets
- Show constraint descriptions
- Show constraint source (tool / rule / inheritance)

The UI MAY NOT:
- Enforce constraints
- Modify constraints
- Infer legality of actions
- Predict constraint violations

---

## Constraint Types (Non-Exhaustive)

- symmetry
- fixed-axis
- locked-dimension
- reference-plane
- parent-lock

---

## Data Source

All constraint data MUST come from:
- kernel constraint registry
- snapshot metadata

No client-side derivation is permitted.

---

## Display Rules

- Constraints are visible only when a snapshot is active
- Constraints are read-only
- Constraints must include:
  - id
  - type
  - affected targets
  - description

---

## Forbidden

- Client-side constraint math
- Constraint suppression
- Auto-hiding constraints during transform
