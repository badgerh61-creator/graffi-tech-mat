# Tier 7.56 — Variant Sets

## Purpose (LOCKED)
Allow users to save and apply named design variants that capture a deterministic
subset of scene appearance data for fast comparison and review.

## Authoritative Storage
snapshot.decor_state.variant_sets : list[VariantSet]

VariantSet:
{
  "id": "var-...",
  "name": "string",
  "payload": {
    "material_overrides": { ... },
    "decals": [ ... ],
    "object_enabled": {
      "obj-1": true,
      "obj-2": false
    }
  },
  "version": 1
}

## Scope of Tier 7.56
This tier captures and applies:
- decor_state.material_overrides
- decor_state.decals
- body_state.objects[*].enabled

It does NOT yet capture:
- transforms
- hierarchy
- camera
- layout

## Tools (Governed)
VARIANT_SAVE
payload:
{
  "name": "string"
}

VARIANT_APPLY
payload:
{
  "variant_id": "var-..."
}

VARIANT_DELETE
payload:
{
  "variant_id": "var-..."
}

## Save Rules
- captures current authoritative state from active snapshot
- saves deterministic deep copy
- variant list sorted by id after apply

## Apply Rules
- replace current:
  - decor_state.material_overrides
  - decor_state.decals
  - body_state.objects[*].enabled
  with captured variant payload
- object enabled only applies to object ids that exist in current snapshot
- no geometry mutation

## Determinism
- same snapshot state + same save request => same saved payload except generated id
- apply uses exact saved data
- missing objects are ignored safely during object_enabled restore

## Invariants
- no client-side snapshot mutation
- one governed commit per action
- no partial apply
- variant operations require draft + lock owned
