# Tier 7.4 — Transform Gizmo + Axis Locks (UI)

## Purpose (LOCKED)
Provide UX for transform handles (translate/rotate/scale) with axis locks,
without bypassing tool governance.

## Invariants (NON-NEGOTIABLE)
1. Gizmo never mutates state directly.
2. Gizmo emits a tool invocation payload only.
3. Axis locks are explicit in payload.
4. Result must be a child draft snapshot (immutability preserved).
5. Draft lock is required for execution.

## UI Behavior
- User selects target.
- Gizmo displays axes.
- Dragging emits deltas (x/y/z) or angle/scale factors.
- Axis locks restrict which components are included.

## Payload Additions
Transform payload MAY include:
- axis_lock: "x"|"y"|"z"|"xy"|"xz"|"yz"|"xyz" (default "xyz")
- drag_source: "gizmo" (for audit/telemetry only)

## Kernel Rules
- axis_lock affects which numeric params are applied:
  - lock "x" => only x is applied (y,z ignored)
  - lock "xy" => x,y applied, z ignored, etc.
- invalid axis_lock => 422

## Audit
action: "snapshot.transform"
extra:
- axis_lock
