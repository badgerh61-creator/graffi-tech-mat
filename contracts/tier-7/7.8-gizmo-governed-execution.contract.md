# Tier 7.8 — Gizmo → Governed Execution Wiring

## Purpose (LOCKED)
Wire Transform Gizmo commits into the governed proposal execution path
without introducing any bypass route.

## Authoritative Endpoints (Existing)
- POST /assistant/proposals/evaluate
- POST /assistant/proposals/apply
- (optional) POST /assistant/proposals/preview

## Invariants
1. UI never mutates snapshots directly.
2. Every commit is executed via the same kernel gate path:
   - draft-only
   - draft lock required
   - station/tool/flow/mode enforced
3. Apply requires explicit user confirmation (UI must send confirm=true).
4. If preview returns a payload_hash, apply must include it (if backend requires).
5. After apply succeeds, UI must switch active snapshot to new_snapshot_id.

## Request Shapes (canonical)
Evaluate:
{ "snapshot_id": int, "proposal": { "station": str, "tool": str, "payload": object } }

Preview (optional):
{ "snapshot_id": int, "proposal": { "station": str, "tool": str, "payload": object } }

Apply:
{
  "proposal_id": "uuid|string",
  "snapshot_id": int,
  "confirm": true,
  "payload_hash": "sha256" (optional)
}

## UI behavior
On gizmo commit:
1) call evaluate
2) if rejected: show reason (no apply)
3) if allowed:
   - optionally call preview (non-blocking if unavailable)
   - ask user confirmation (Tier 7.8: simple confirm=true is OK)
   - call apply
4) on success: setActiveSnapshot(new_snapshot_id) + refresh snapshot list
