# Tier 7.51 — Grouping / Parenting

## Purpose (LOCKED)
Add hierarchical grouping and parenting to the scene graph so users can organize
and transform assemblies like a real editor.

## Authoritative Storage
snapshot.body_state.objects : list[SceneObject]

Extended SceneObject:
{
  "id": "obj-...",
  "kind": "model_ref" | "group" | ...,
  "name": "string",
  "asset_id": "asset-..." | null,
  "parent_id": "obj-..." | null,
  "transform": {
    "pos": { "x": number, "y": number, "z": number },
    "rot": { "x": number, "y": number, "z": number },
    "scale": { "x": number, "y": number, "z": number }
  },
  "layers": ["default"],
  "enabled": true,
  "version": 1
}

## Tools (Governed)
SCENE_CREATE_GROUP
payload:
{
  "name": "string"
}

SCENE_PARENT_OBJECT
payload:
{
  "object_id": "obj-...",
  "parent_id": "obj-..."
}

SCENE_UNPARENT_OBJECT
payload:
{
  "object_id": "obj-..."
}

## Group Rules
- groups are scene objects with kind="group"
- groups have no asset_id
- groups may be parented later, but Tier 7.51 only requires one-level-safe support

## Parenting Rules
- object parent_id becomes parent object id
- parent must exist
- object may not parent to itself
- cycles are forbidden
- unparent sets parent_id=null

## Outliner Behavior
- hierarchical tree view
- deterministic order: parent first, children sorted by id
- selecting a row selects that object

## Viewer Behavior
- child transforms are applied relative to parent group
- hidden/disabled parent hides children through normal scene graph visibility

## Invariants
- no client-side snapshot mutation
- one governed commit per action
- no cycles
- deterministic tree ordering

## Forbidden
- self-parenting
- cyclic parenting
- mutating source ids
