# Tier 6S.6 — Scenario Templates + Presets (Reusable Lab Inputs)

## Purpose (LOCKED)
Provide reusable, structured experiment presets:
- built-in scenario templates
- template inheritance (extend/override)
- deterministic scenario_hash for reproducibility

## Invariants (NON-NEGOTIABLE)
1. Templates are code-defined (registry), not DB-owned.
2. Scenario creation computes scenario_hash deterministically:
   stable_hash(normalized_scenario + template_key + template_version + engine_version)
3. Template inheritance must be deterministic (base -> derived -> overrides).
4. No snapshot mutation. No artifact mutation.

## API (Additive)

### GET /simulation/templates
200:
{
  "templates": [
    { "key": "accel_0_60_v1", "name": "...", "version": "v1", "extends": null, "defaults": {...} },
    ...
  ]
}

### POST /simulation/scenarios/from-template
Body:
{
  "project_id": int,
  "name": string,
  "template_key": string,
  "engine_version": "pseudo-v1",
  "overrides": { ... }   # optional
}

200:
{
  "scenario_id": int,
  "scenario_hash": string,
  "template_key": string
}

## Forbidden
- non-deterministic hashing
- template registry reads mutating DB
