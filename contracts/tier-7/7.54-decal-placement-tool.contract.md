# Tier 7.54 — Decal Placement Tool

## Purpose (LOCKED)
Allow users to place decals directly onto mesh surfaces in the viewport with:
- hover preview
- click-to-place
- surface-aligned orientation
- size / rotation controls
- single governed create commit

## Inputs
- selected decal asset (asset_id or asset_ref)
- current selection filter / mesh picking
- placement tool state
- active snapshot in EDIT mode

## UI Behavior
- entering decal placement mode does not mutate snapshot
- moving mouse over a valid mesh shows preview decal
- clicking confirms placement and sends one DECAL_CREATE commit
- Escape cancels placement preview
- user can set:
  - uniform size
  - local rotation about surface normal
  - opacity
  - blend

## Placement Rules
- placement target must be a picked mesh/object target_id
- preview position derives from raycast hit point
- preview orientation aligns decal forward axis to surface normal
- z_offset applied deterministically
- if no valid hit, no placement commit occurs

## Tool Payload
DECAL_CREATE
payload:
{
  "target_id": "<objectId>::<mesh_path>" | "<objectId>",
  "asset_id": "asset-..." | null,
  "asset_ref": "..." | null,
  "initial": {
    "position": {x,y,z},
    "rotation_euler": {x,y,z},
    "scale": {x,y,z},
    "opacity": 0..1,
    "blend": "normal" | "multiply" | "add",
    "z_offset": number,
    "meta": { "name": "string" }
  }
}

## Determinism
- same hit point + same normal + same tool controls => same preview + same payload
- preview and commit use same transform math
- no random rotation or offset

## Invariants
- no backend writes during preview
- one commit per confirmed click
- cancel clears preview only
- snapshot unchanged until apply succeeds

## Forbidden
- continuous paint mode
- multiple commits during drag
- client-side snapshot mutation
