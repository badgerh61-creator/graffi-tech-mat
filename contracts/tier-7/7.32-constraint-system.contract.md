# Tier 7.32 — Constraint System (Governed, Deterministic)

## Purpose (LOCKED)
Add deterministic constraint evaluation to the governed tool pipeline so invalid
transform commits are blocked before snapshot mutation.

## Where it runs
Constraint evaluation occurs during:
- /assistant/proposals/evaluate
and is enforced during:
- /assistant/proposals/apply

## Constraint Model
Constraints exist in snapshot payload (authoritative):
- body_state["constraints"] : list[Constraint]

Constraint:
{
  "id": "string",
  "kind": "symmetry" | "bounds" | "locked_axis" | "custom",
  "target_id": "object::mesh_path",
  "params": { ... },
  "enabled": true
}

## Minimal Supported Constraints (Tier 7.32)
1) bounds:
   - target must remain within world bounds
   - params: { "min": {x,y,z}, "max": {x,y,z} }
2) locked_axis:
   - blocks translate/rotate/scale along specific axes
   - params: { "axes": ["x","y","z"], "tools": ["TRANSLATE","ROTATE","SCALE"] }
3) symmetry (stub-compatible):
   - blocks x != 0 when plane is centerline
   - params: { "plane": "vehicle_centerline" }

## Evaluation Output (canonical)
Evaluate response MUST include:
- ok: boolean
- violations: [
    { "constraint_id": string, "kind": string, "message": string, "data": object }
  ]

If violations exist:
- ok=false
- proposal MUST NOT be applicable

## Invariants
- Deterministic: same snapshot + same proposed change => same violations
- Read-only during evaluate (no DB writes)
- Apply may only proceed if evaluate ok=true
- No solver in this tier (no automatic fixes)

## Forbidden
- silent acceptance of violations
- mutation during evaluation
- nondeterministic/random behavior
