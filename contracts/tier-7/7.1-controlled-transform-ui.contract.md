# Tier 7.1 — Controlled Transform UI (Selection + Move/Rotate/Scale)

## Purpose (LOCKED)
Provide an editor UI that allows a user to:
- select a target (panel/curve/surface)
- perform a transform (translate/rotate/scale)
without ever mutating snapshots directly.

The UI must only request mutation through the governed tool execution path.

## Non-Negotiable Invariants
1. Every transform creates a NEW draft snapshot (child).
2. The parent snapshot is never mutated.
3. Only draft snapshots may be transformed.
4. Draft ownership lock (Phase U) is required.
5. Tool registry + flow + mode enforcement (Phase T) must be respected.
6. All transforms emit an audit event.

## Canonical Tools (Tier 7.1)
- TRANSLATE
- ROTATE
- SCALE

## Target Resolution
- UI maintains a selected `target_id` (string).
- `target_id` is treated as an opaque identifier; the backend does not “guess”.
- Backend may reject unknown/unresolvable targets (422) in future tiers.

## API (Additive)
POST /tools/execute

Request JSON:
{
  "snapshot_id": int,
  "station": "geometry",
  "tool": "TRANSLATE" | "ROTATE" | "SCALE",
  "payload": {
    "target_id": "panel-1",
    "params": {...}
  }
}

Success 200:
{
  "new_snapshot_id": int
}

Failure Modes
- 401: not authenticated
- 403: lock missing / insufficient permission
- 404: snapshot not found
- 409: snapshot not draft OR mode/flow mismatch
- 422: invalid tool or payload

## Audit (Required)
action: "snapshot.transform"
extra:
  - parent_snapshot_id
  - tool
  - station
  - target_id

## Forbidden
- direct snapshot mutation (no in-place updates)
- transforms on completed snapshots
- bypassing locks via assistant or UI
- UI-driven “editable flags” that override kernel truth
