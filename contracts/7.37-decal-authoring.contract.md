# Tier 7.37 — Decal Authoring UI (Governed, Deterministic)

## Purpose (LOCKED)
Introduce authoring of decal entities (stickers/labels/logos) as governed edits:
- create decal
- update transform/props
- delete decal

Decals live in decor_state and render in the Three.js viewer.

## Storage (Authoritative)
snapshot.decor_state.decals : list[Decal]

Decal shape (canonical):
{
  "id": "dec-<uuid>",
  "enabled": true,
  "target_id": "object::mesh_path" | "object::<objectId>",
  "asset_ref": "asset://..." | "http(s)://..." | "builtin://...",
  "position": { "x": 0, "y": 0, "z": 0 },
  "rotation_euler": { "x": 0, "y": 0, "z": 0 },  # degrees
  "scale": { "x": 1, "y": 1, "z": 1 },
  "opacity": 1.0,
  "blend": "normal" | "multiply" | "add",
  "z_offset": 0.001,
  "meta": { "name": "string" }
}

## Tools (Governed)
1) DECAL_CREATE
payload:
{
  "target_id": "...",
  "asset_ref": "...",
  "initial": { position, rotation_euler, scale, opacity, blend, z_offset, meta? }
}

2) DECAL_UPDATE
payload:
{
  "decal_id": "dec-...",
  "patch": { any decal fields except id }
}

3) DECAL_DELETE
payload:
{ "decal_id": "dec-..." }

## Evaluate Rules
- Deterministic validation
- asset_ref must be non-empty string
- opacity must be [0..1]
- blend in allowed set
- target_id required for create
- update/delete require existing decal_id

## Apply Rules
- Applies mutation only by creating a child snapshot (never in-place)
- Writes only to decor_state.decals
- No geometry writes

## Viewer
- Three.js viewer must render decals from decor_state.decals
- Deterministic draw ordering: stable sort by decal.id

## Invariants
- No backend writes during drag/preview
- One commit per action (create/update/delete)
- Stable id generation occurs in backend apply (or deterministic in client if already established)
