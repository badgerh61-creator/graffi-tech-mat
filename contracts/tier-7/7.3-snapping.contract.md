# Tier 7.3 — Snapping (UI-guided, kernel-validated)

## Purpose (LOCKED)
Enable snapping during transform operations using reference frames (Tier 7.2),
without violating kernel governance.

## Invariants (NON-NEGOTIABLE)
1. Snapping is only applied on draft snapshots.
2. Snapping never mutates the input snapshot; it creates a child draft snapshot.
3. Snapping parameters are explicit in the tool payload (no hidden defaults).
4. Snapping is deterministic: same input -> same snapped output.
5. All snapped transforms must be audited.

## Payload Shape (Additive)
Transform tool payload MAY include:
- frame_id: string (e.g. "world_xy")
- snap: boolean
- snap_step: number (e.g. 0.1)
- snap_origin: "frame" | "world" (default "frame")
- snap_axes: ["x","y","z"] subset (default all)

## Behavior
If snap=true:
- numeric params are quantized by snap_step along allowed axes.
- snapping uses the selected frame_id for axis interpretation (Tier 7.2).
- if frame_id is unknown -> reject 422.

## API / Execution
Snapping is NOT a new endpoint.
It is applied during tool execution:
- via your governed transform path (Phase T / Tier 7.1).

## Failure Modes
- 404 snapshot not found (handled upstream by tool executor)
- 409 snapshot not draft
- 403 lock missing (Phase U)
- 422 unknown frame_id or invalid snap_step

## Audit
action: "snapshot.transform"
extra must include:
- snap: true/false
- frame_id (if provided)
- snap_step (if provided)
