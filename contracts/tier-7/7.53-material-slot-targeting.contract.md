# Tier 7.53 — Material Slot Targeting

## Purpose (LOCKED)
Allow users to inspect and edit material slots on a selected mesh/object so
material overrides can target the exact slot instead of the whole object only.

## Authoritative Storage
snapshot.decor_state.material_overrides : dict

Canonical key forms:
1) object-level override
   "<object_id>"

2) mesh-level override
   "<object_id>::<mesh_path>"

3) slot-level override
   "<object_id>::<mesh_path>::slot:<slot_name>"

Override value:
{
  "preset": "<preset_id>",
  "params": { ... },
  "version": 1
}

## Slot Metadata (Viewer-derived / UI-read-only)
Material slots are discovered from the loaded scene mesh:
{
  "target_id": "<object_id>::<mesh_path>",
  "slots": [
    { "name": "BodyPaint", "index": 0 },
    { "name": "Trim", "index": 1 }
  ]
}

## Tools (Governed)
MATERIAL_SET_SLOT_PRESET
payload:
{
  "target_id": "<object_id>::<mesh_path>",
  "slot_name": "<slot_name>",
  "preset": "<preset_id>"
}

MATERIAL_CLEAR_SLOT_OVERRIDE
payload:
{
  "target_id": "<object_id>::<mesh_path>",
  "slot_name": "<slot_name>"
}

## Evaluate Rules
- target_id required
- slot_name required and non-empty
- preset required for set
- preset must exist in preset registry
- clear is allowed even if override missing (no-op)

## Apply Rules
- mutate only decor_state.material_overrides
- slot-level key must be canonical:
  "<target_id>::slot:<slot_name>"
- no geometry mutation

## Precedence
1) slot-level override
2) mesh-level override
3) object-level override
4) original model material

## Determinism
- same target + same slot + same preset => same stored override
- slot keys must be stable
- no random slot naming

## Invariants
- no backend writes during inspection
- one governed commit per slot action
- slot discovery is UI/viewer-only
