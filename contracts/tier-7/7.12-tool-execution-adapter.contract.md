# Tier 7.12 — Tool Execution Adapter (Frontend)

## Purpose (LOCKED)
Provide one canonical frontend gateway for governed tool execution.

## Inputs
- snapshot_id (int)
- station (string)
- tool (string)
- payload (object)
- strategy: "proposals" | "tools" (default "proposals")

## Outputs
Adapter returns a normalized shape:
- ok: boolean
- data?: response json (if ok)
- error?: { kind, status, detail }

## Invariants
1. UI must not call fetch() for tool execution directly outside this adapter.
2. Adapter always sends Authorization: Bearer <token> when available.
3. Adapter always returns a normalized error shape (never throws by default).
4. Default execution strategy is the governed proposals path:
   /assistant/proposals/evaluate -> /assistant/proposals/apply
5. Adapter must surface "why blocked" when kernel rejects (allowed=false).

## Error kinds (normalized)
- "unauthenticated" (401)
- "forbidden" (403)
- "conflict" (409)
- "validation" (422)
- "network" (fetch/parse failure)
- "unknown"

## Forbidden
- Multiple competing adapters
- Tool components embedding their own endpoint logic
