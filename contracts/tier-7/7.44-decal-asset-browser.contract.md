# Tier 7.44 — Decal Asset Browser (Registry + Governed Assign)

## Purpose (LOCKED)
Introduce a deterministic decal asset browser so decals can use real images:
- list available decal assets from a stable registry endpoint
- assign an asset to a decal via governed commit

## Storage (Authoritative)
decor_state.decals: list[Decal]

Decal:
{
  "id": "dec-...",
  "asset_id": "asset-..." | null,
  "url": "http..." | null,              # derived from asset_id (optional cached)
  "position": {x,y,z},
  "rotation_euler": {x,y,z},            # degrees
  "scale": {x,y,z},
  "opacity": 0..1,
  "enabled": true,
  "version": 1
}

Asset Registry
GET /decor/decal-assets -> { assets: [{id, name, url, tags[]}] }

## Tools (Governed)
DECAL_SET_ASSET
payload:
{
  "decal_id": "dec-...",
  "asset_id": "asset-..."
}

## Evaluate Rules
- decal_id exists
- asset_id exists in registry
- snapshot must be draft + lock owned (enforced by existing governance)
- no writes in evaluate

## Apply Rules
- mutate only decor_state.decals[*].asset_id (and optionally cached url)
- deterministic, reversible by setting asset_id=null (optional later)

## Viewer
- decal material loads texture from asset url (cache by asset_id)
- deterministic fallback if texture fails: use checker placeholder

## Invariants
- no upload
- no backend mutation outside tool apply
- stable asset ordering
