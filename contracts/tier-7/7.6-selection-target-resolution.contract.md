# Tier 7.6 — Selection & Target Resolution Rules (Deterministic)

## Purpose (LOCKED)
Define deterministic rules for resolving:
- active target (single “focus”)
- selection set (multi-select)
- hit-testing priority (what gets selected on click)
- stable ordering for payloads and audits

## Invariants
1. Resolution is deterministic: same inputs => same outputs.
2. UI may compute hit candidates, but backend normalizes + validates ordering.
3. Selection ordering must be stable (lexicographic by id unless explicitly overridden).
4. active_target_id must be a member of selected_target_ids (if selection set exists).
5. Empty selection is valid (clears selection), but transform tools require targets.

## Inputs (UI -> backend payload)
- hit_candidates: [{ target_id: string, kind: "panel"|"curve"|"edge"|"vertex", depth: number, priority?: number }]
- modifiers: { shift: bool, ctrl: bool } (optional)
- previous_selection: { selected_target_ids: [], active_target_id: string|null } (optional)

## Resolution Rules (canonical)
Given hit_candidates (possibly empty):

A) Candidate Sort (highest wins)
1. priority (desc) if provided
2. kind priority (vertex > edge > curve > panel)
3. depth (asc)  # nearer wins
4. target_id (asc)  # tie-breaker

B) Click Behavior
- No modifier:
  - selected_target_ids = [winner.target_id] (or [])
  - active_target_id = winner.target_id (or null)
- Shift:
  - toggles winner in selected_target_ids
  - active_target_id becomes winner if winner selected, else first item (or null)
- Ctrl:
  - adds winner to selected_target_ids (no toggle)
  - active_target_id becomes winner

C) Ordering
- selected_target_ids must always be stored sorted asc for stability.

## API (optional helper endpoint)
POST /selection/resolve
Body:
{
  "hit_candidates": [...],
  "modifiers": {"shift": false, "ctrl": false},
  "previous_selection": {...}
}

Response:
{
  "selected_target_ids": [...],
  "active_target_id": "...|null",
  "winner": "...|null"
}

## Forbidden
- active_target_id not in selected_target_ids when selected_target_ids is non-empty
- non-deterministic ordering (e.g. insertion-order drift)
