# Tier 2.3 — Undo / Redo UI (Graph-aware)

## Purpose
Expose snapshot history as a navigable graph and allow users to request
movement between nodes.

---

## Definitions

- History Graph: Directed acyclic graph of snapshots
- Active Snapshot: Current node
- Parent Snapshot: Direct ancestor
- Child Snapshots: Direct descendants

---

## UI Responsibilities

The UI MAY:
- Display history nodes
- Display parent/child relationships
- Highlight active snapshot
- Issue navigation requests

The UI MAY NOT:
- Mutate snapshots
- Flatten branches
- Infer legality
- Execute undo/redo directly

---

## Navigation Semantics

- Undo = request move to parent snapshot
- Redo = request move to selected child snapshot
- Navigation requests are advisory only

---

## Data Source

All history data MUST come from:
- kernel snapshot graph
- immutable snapshot metadata

---

## Forbidden

- Linear stack assumptions
- Client-side history reconstruction
- Silent auto-navigation
