# Tier 7.36 — Edit Session Header + Lock Status + Reasons

## Purpose (LOCKED)
Provide a single, always-visible session header that shows:
- current mode (READ / EDIT)
- snapshot id + status
- lock status (owned / not owned / missing)
- explicit reasons why editing tools are disabled

## UI Requirements
The header must show:
- Project name/id (if available)
- Active snapshot: {id, status, parent_snapshot_id?}
- Mode:
  - READ if snapshot.status != "draft"
  - EDIT if snapshot.status == "draft"
- Lock:
  - owned by me -> "LOCK: Owned"
  - owned by someone else -> "LOCK: Taken"
  - no lock -> "LOCK: Missing"
  - unknown -> "LOCK: Unknown"

## Why-Blocked Reasons (canonical)
Compute reasons as a deterministic list:
- NOT_DRAFT (snapshot is completed)
- NO_LOCK (draft but lock not owned)
- ROLE_FORBIDDEN (user role lacks edit capability)
- STATION_FORBIDDEN (station/capability disallows tool)
- SNAPSHOT_MISSING (no snapshot loaded)
- LOADING (scene/snapshot loading)

UI must render reasons in stable order.

## Determinism Rules
- Reasons list ordering is fixed and stable.
- UI must not guess lock ownership; it must come from authoritative lock status.

## Invariants
- No snapshot writes
- No lock writes here (7.35 handles acquire/release)
- No backend mutation
- UI-only indicators
