# Tier 6G.11 — Material Override System (Draft-only, Non-destructive)

## Purpose (LOCKED)
Allow visual material/paint overrides to be applied non-destructively in the viewer,
stored as snapshot metadata, without mutating geometry.

## Storage (Authoritative)
Overrides live in snapshot.body_state:

body_state["material_overrides"] : list[MaterialOverride]

MaterialOverride:
{
  "id": "ovr-uuid-or-slug",
  "enabled": true,
  "target": {
    "object_key": "object_id" | "object_id@instance_id",
    "mesh_path": "A/B/C" | null  // null = apply to whole object instance
  },
  "material": {
    "color": "#RRGGBB" | null,
    "opacity": number | null,
    "metalness": number | null,
    "roughness": number | null,
    "emissive": "#RRGGBB" | null
  }
}

## Apply Rules (Viewer)
1) Overrides are applied in deterministic order:
   - sort by override.id lexicographically
2) For each override:
   - if target.mesh_path is null: apply to all meshes under object group
   - else: resolve mesh by mesh_path and apply to that node only
3) Override values are clamped:
   - opacity ∈ [0,1]
   - metalness/roughness ∈ [0,1]
4) Unknown fields are ignored (forward-compatible)

## Invariants
- Non-destructive: original materials remain untouched in source asset;
  viewer must clone materials before applying overrides.
- Read-only in this tier: no backend writes required.
- Deterministic: same snapshot + same overrides => same visual output.

## Forbidden
- mutating shared materials across instances (must clone per mesh)
- nondeterministic override order
- snapshot mutation from viewer
