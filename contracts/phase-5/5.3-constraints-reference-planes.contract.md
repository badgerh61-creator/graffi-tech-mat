# Phase 5.3 — Constraints & Reference Planes

## Purpose
Define geometric constraints and immutable reference planes used to validate transforms.

---

## Reference Planes

Reference planes define global or local invariants.

Examples:
- ground_plane
- vehicle_centerline
- axle_front
- axle_rear

Reference planes:
- Are immutable
- Exist per snapshot
- Cannot be transformed

---

## Constraint Types

- symmetry (across reference plane)
- locked_axis (x | y | z)
- min_distance
- max_distance
- coincident_to_plane

---

## Rules

- Constraints are evaluated before transform application
- Failed constraints block the transform
- Constraints never mutate geometry
- Constraints are snapshot-scoped
- Constraints apply only to draft snapshots

---

## API Endpoint

POST /projects/{project_id}/snapshots/{snapshot_id}/validate-transform

---

## Request Body

```json
{
  "target_id": "string",
  "operation": "translate | rotate | scale",
  "params": {},
  "constraints": ["symmetry", "locked_axis"]
}
```

---

## Success Response

```json
{
  "valid": true
}
```

---

## Failure Response

```json
{
  "valid": false,
  "violations": [
    {
      "constraint": "symmetry",
      "message": "Target must remain symmetric across vehicle_centerline"
    }
  ]
}
```

---

## Forbidden

- Auto-correcting geometry
- Applying transforms after failed validation
- Editing reference planes
