# Tier 2.1 — Controlled Transform UI

## Purpose
Expose transform tools in the UI while preserving kernel authority.

---

## Scope

The UI may:
- Display transform tools (translate, rotate, scale)
- Enable or disable tools based on kernel state
- Submit transform commands
- Display rejection reasons

The UI may NOT:
- Perform transforms locally
- Modify snapshots directly
- Bypass constraints
- Auto-correct invalid input

---

## Preconditions for Tool Enablement

A transform tool is enabled iff:
- Active snapshot exists
- Snapshot.status == "draft"
- User has edit capability
- Current station allows transforms
- Current mode == "editing"
- Flow graph allows transform step

---

## Execution Flow

1. User selects transform tool
2. UI queries kernel for legality
3. UI collects parameters
4. UI submits transform command
5. Kernel returns:
   - new draft snapshot OR
   - rejection reason
6. UI reflects result

---

## Failure Handling

If transform is rejected:
- No state mutation occurs
- Rejection reason is displayed
- UI state remains unchanged

---

## Forbidden

- Client-side mutation
- Silent failure
- Optimistic snapshot creation
- Constraint masking
