# Tier 7.57 — Asset Placement Palette

## Purpose (LOCKED)
Provide a real asset placement workflow for scene authoring:
- searchable asset browser
- category/group filters
- recent assets
- favorites
- click-to-place model into scene

## Asset Registry (Read-only)
GET /assets/models -> {
  "assets": [
    {
      "id": "asset-...",
      "name": "string",
      "url": "string",
      "kind": "vehicle" | "prop" | "wheel" | "environment" | ...,
      "tags": ["..."],
      "category": "string"
    }
  ]
}

## Local UI Metadata (client-side only)
Palette UI may maintain:
- recent asset ids
- favorite asset ids
This metadata is UI-only and does not mutate snapshots.

## Placement Tool (Governed)
SCENE_ADD_MODEL_REF
payload:
{
  "asset_id": "asset-...",
  "name": "string?",
  "transform": {
    "pos": { "x": number, "y": number, "z": number },
    "rot": { "x": number, "y": number, "z": number },
    "scale": { "x": number, "y": number, "z": number }
  }
}

## Tier 7.57 Scope
- browser/filter/search assets
- mark favorites locally
- track recent locally
- click "place" to add at default transform
- optional "placement mode" hook for future drag-place

## Determinism
- asset ordering is stable by id unless explicit filtered grouping is applied
- same selected asset + same default transform => same SCENE_ADD_MODEL_REF payload
- favorites/recent ordering is deterministic in UI

## Invariants
- no backend writes during browsing/filtering/favoriting
- one governed commit per placement
- no snapshot mutation until apply succeeds
- asset registry remains authoritative for asset definitions

## Forbidden
- direct client insertion into body_state.objects
- hidden mutable asset registry behavior
