# Tier 7.13 — Selection & Target Resolution UI

## Purpose (LOCKED)
Define deterministic selection state + target resolution for UI tools.

## Definitions
- "selection": UI-owned state describing what the user has selected.
- "target": the resolved tool target (string id) derived from selection.

## Selection Model
SelectionState:
- primary: { kind: "panel"|"curve"|"surface"|"vertex"|"edge"|null, id: string|null }
- secondary: array of { kind, id }
- hovered: { kind, id } | null
- lastUpdatedAt: epoch_ms

## Resolution Rules (LOCKED)
1. primary determines active tool target.
2. hovered NEVER becomes target unless explicitly selected.
3. If primary is null, tool execution MUST be blocked at UI layer with reason "no_selection".
4. Resolution is pure: same SelectionState => same resolved target.

## API / Integration
- UI components emit selection events only through SelectionStore actions.
- Tool invocation payloads use resolved target_id (string).

## Forbidden
- Tool components storing their own selection state
- Implicit selection changes during tool execution
- Using array[0] heuristics
