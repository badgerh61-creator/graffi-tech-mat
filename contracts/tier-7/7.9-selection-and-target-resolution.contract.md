# Tier 7.9 — Selection State & Target Resolution (UI)

## Purpose (LOCKED)
Introduce canonical selection state in the frontend and resolve the active target ID
used by gizmos and tool proposals.

## Invariants
1. Selection is UI state only (no backend writes).
2. Selection is deterministic and explicit:
   - selectedId: string|null
3. Selection does NOT imply authority:
   - it never bypasses lock/mode/flow/tool gates.
4. Target resolution is separate from visualization:
   - resolveSelectedTarget(snapshot, selectedId) returns either a valid target_id or null.

## Outputs
- selectedTargetId: string|null
- selectionReason: string|null

## Forbidden
- hardcoded target ids in production code
- implicit "first object" auto-selection without user action
